<objective>
Fix the gap where `actions/cache` in `ci.yml` is not pinned to a SHA, satisfying SEC-01.
Additionally, enforce least-privilege `permissions` across all GitHub Actions workflows to satisfy SEC-02.
</objective>

<context>
@.planning/phases/112-security-supply-chain-release-hardening/112-VERIFICATION.md
</context>

<tasks>

<task type="auto">
  <name>Task 1: Pin actions/cache in ci.yml</name>
  <files>.github/workflows/ci.yml</files>
  <read_first>
    - .github/workflows/ci.yml
  </read_first>
  <action>
    Find all usages of `actions/cache@v4`, `actions/cache/restore@v4`, and `actions/cache/save@v4` in `.github/workflows/ci.yml`.
    Look up the exact SHA for the current `v4` release (e.g. v4.2.0 or latest v4 tag) via GitHub API or CLI (e.g. `curl -sL https://api.github.com/repos/actions/cache/commits/v4 | jq -r .sha`).
    Update `.github/workflows/ci.yml` to replace the `@v4` tags with `@<sha> # v4.x.x` format.
  </action>
  <verify>
    <automated>! grep -q "actions/cache.*@v4$" .github/workflows/ci.yml</automated>
  </verify>
  <done>actions/cache is pinned to an immutable SHA in ci.yml.</done>
</task>

<task type="auto">
  <name>Task 2: Enforce least-privilege permissions</name>
  <files>
    .github/workflows/ci.yml
    .github/workflows/audit.yml
    .github/workflows/release.yml
  </files>
  <read_first>
    - .github/workflows/ci.yml
    - .github/workflows/audit.yml
    - .github/workflows/release.yml
  </read_first>
  <action>
    Update all GitHub Actions workflows to enforce least-privilege permissions at the workflow or job level.
    By default, permissions should be `read-all` or strictly restricted.
    
    1. For `.github/workflows/ci.yml`, add top-level `permissions: contents: read`.
    2. For `.github/workflows/audit.yml`, since it uses `peter-evans/create-issue-from-file`, it requires issue writing. Set `permissions: contents: read, issues: write`.
    3. For `.github/workflows/release.yml`, assuming it just builds and publishes via Hex, it needs `contents: read`. If it creates a GitHub Release, it might need `contents: write`. Set appropriately based on its current behavior.
  </action>
  <verify>
    <automated>grep -q "permissions:" .github/workflows/ci.yml && grep -q "permissions:" .github/workflows/audit.yml && grep -q "permissions:" .github/workflows/release.yml</automated>
  </verify>
  <done>All workflows specify least-privilege permissions.</done>
</task>

</tasks>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-112-04-1 | Tampering | actions/cache | mitigate | Pin to immutable SHA to ensure the cache action itself cannot be silently altered. |
| T-112-04-2 | Elevation of Privilege | GITHUB_TOKEN | mitigate | Restrict `permissions:` so that a compromised token cannot modify repo contents or settings without explicit job-level consent. |
