## Architecture Patterns

### System Architecture Diagram

```text
Existing Rendro fixture PDFs
  -> Node advisory observer (`scripts/pdfjs_observer/observe.mjs`)
    -> `pdfjs-dist/legacy/build/pdf.mjs` `getDocument({ data, cMapUrl, cMapPacked, standardFontDataUrl })`
      -> document metadata (`version`, `numPages`, Node/npm environment)
      -> per-page viewport dimensions via `getPage(n).getViewport({ scale: 1.0 })`
      -> optional first page render via `pdfDocument.canvasFactory` and `page.render(...).promise`
        -> optional PNG SHA-256
    -> compact committed JSON in `priv/pdfjs_observations/*.json`
      -> docs-contract validates schema and wording
      -> advisory CI checks observations only, with no `needs:` and `continue-on-error: true`
```

This data flow mirrors the official PDF.js Node examples for `getDocument`, page iteration, viewport dimensions, canvas rendering, and cleanup. [CITED: raw.githubusercontent.com/mozilla/pdf.js/master/examples/node/getinfo.mjs] [CITED: raw.githubusercontent.com/mozilla/pdf.js/master/examples/node/pdf2png/pdf2png.mjs]

### Pattern 1: Metadata-First Observation

**What:** Load each PDF as a `Uint8Array`, record `pdfjsLib.version`, `process.version`, `doc.numPages`, and each page viewport width/height at scale `1.0`. [CITED: mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html] [CITED: mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFDocumentProxy.html] [CITED: mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFPageProxy.html]  
**When to use:** Always; this is the stable observation contract for PDFJS-01. [VERIFIED: codebase grep `.planning/REQUIREMENTS.md`]  
**Example:**

```javascript
// Source: https://raw.githubusercontent.com/mozilla/pdf.js/master/examples/node/getinfo.mjs
// Adapted for Rendro advisory observations.
import fs from "node:fs";
import path from "node:path";
import { fileURLToPath } from "node:url";
import * as pdfjsLib from "pdfjs-dist/legacy/build/pdf.mjs";

const here = path.dirname(fileURLToPath(import.meta.url));
const pkgRoot = path.join(here, "node_modules/pdfjs-dist");
const data = new Uint8Array(fs.readFileSync(process.argv[2]));

const loadingTask = pdfjsLib.getDocument({
  data,
  cMapUrl: path.join(pkgRoot, "cmaps/") + path.sep,
  cMapPacked: true,
  standardFontDataUrl: path.join(pkgRoot, "standard_fonts/") + path.sep
});

const doc = await loadingTask.promise;
const pages = [];

for (let pageNumber = 1; pageNumber <= doc.numPages; pageNumber += 1) {
  const page = await doc.getPage(pageNumber);
  const viewport = page.getViewport({ scale: 1.0 });
  pages.push({ page_number: pageNumber, width: viewport.width, height: viewport.height });
  page.cleanup();
}

console.log(JSON.stringify({
  observer: "rendro-pdfjs-advisory",
  pdfjs_dist_version: pdfjsLib.version,
  node_version: process.version,
  page_count: doc.numPages,
  pages
}, null, 2));

await doc.cleanup();
```

### Pattern 2: Warning Capture Without Failing on Warnings

**What:** Temporarily intercept `console.warn`/`console.error` during observation, store warnings/errors as arrays, and fail only when the script exits non-zero or the observation cannot be produced. [CITED: mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html] [VERIFIED: codebase grep `.planning/phases/91-pdf-js-advisory-proof-lane/91-CONTEXT.md`]  
**When to use:** Around each fixture observation so PDF.js recovery messages become committed evidence rather than CI blockers. [CITED: github.com/mozilla/pdf.js/wiki/Frequently-Asked-Questions]  
**Example:**

```javascript
// Source: PDF.js exposes a `verbosity` DocumentInitParameters option in official API docs.
const warnings = [];
const errors = [];
const originalWarn = console.warn;
const originalError = console.error;

console.warn = (...args) => warnings.push(args.map(String).join(" "));
console.error = (...args) => errors.push(args.map(String).join(" "));

try {
  // Run getDocument/getPage/render here.
} finally {
  console.warn = originalWarn;
  console.error = originalError;
}
```

## Common Pitfalls

### Pitfall 1: Version Drift Through Floating npm Ranges

**What goes wrong:** `pdfjs-dist` updates alter Node engine requirements, warning text, optional dependency graph, or render output. [VERIFIED: npm registry]  
**Why it happens:** PDF.js moves quickly and its FAQ describes regular beta/stable promotion. [CITED: github.com/mozilla/pdf.js/wiki/Frequently-Asked-Questions]  
**How to avoid:** Use `--save-exact`, commit `package-lock.json`, record `pdfjs_dist_version`, and require explicit observation re-recording for version bumps. [VERIFIED: npm registry] [ASSUMED]  
**Warning signs:** `package.json` uses `^`, observations omit version, or CI runs `npm install` instead of `npm ci`. [ASSUMED]

### Pitfall 2: Node Rendering Assumed Equivalent to Browser or GUI Rendering

**What goes wrong:** Maintainers or docs imply "PDF.js support" from a Node observation. [VERIFIED: codebase grep `.planning/REQUIREMENTS.md`]  
**Why it happens:** PDF.js is a browser-family renderer and includes viewer builds, but a Node script is not Firefox, Chrome, Acrobat, Preview, or mobile GUI UAT. [CITED: raw.githubusercontent.com/mozilla/pdf.js/master/README.md] [VERIFIED: codebase grep `priv/support_matrix.json`]  
**How to avoid:** Use "pinned PDF.js advisory observations" everywhere, keep observations outside support-matrix promotion rows, and add banned phrase tests. [VERIFIED: codebase grep `.planning/phases/91-pdf-js-advisory-proof-lane/91-CONTEXT.md`]  
**Warning signs:** Public copy says unqualified "PDF.js support" or changes `forms.viewers.pdfjs` from `explicit_deferral`. [VERIFIED: codebase grep `priv/support_matrix.json`]

### Pitfall 3: Font/CMap Resource Warnings

**What goes wrong:** PDF.js emits warnings about missing standard fonts/CMaps or renders with fallback differences. [CITED: raw.githubusercontent.com/mozilla/pdf.js/master/examples/node/pdf2png/pdf2png.mjs]  
**Why it happens:** Official Node PNG example passes `cMapUrl`, `cMapPacked`, and `standardFontDataUrl`; Node defaults also differ from web defaults for some font/resource options. [CITED: raw.githubusercontent.com/mozilla/pdf.js/master/examples/node/pdf2png/pdf2png.mjs] [CITED: mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html]  
**How to avoid:** Always point to `node_modules/pdfjs-dist/cmaps/` and `node_modules/pdfjs-dist/standard_fonts/` with trailing path separators. [CITED: raw.githubusercontent.com/mozilla/pdf.js/master/examples/node/pdf2png/pdf2png.mjs]  
**Warning signs:** Observations contain avoidable "fetchStandardFontData" or CMap fetch warnings. [ASSUMED]

### Pitfall 4: Optional Native Canvas Fragility

**What goes wrong:** First-page PNG generation fails on a runner even while metadata observations work. [VERIFIED: npm registry]  
**Why it happens:** `pdfjs-dist@6.0.227` has `@napi-rs/canvas` as an optional dependency, and native optional packages can vary by OS/architecture. [VERIFIED: npm registry]  
**How to avoid:** Make PNG hash optional; metadata observations are the required part of PDFJS-01, while PNG hashing is included only after the pinned Ubuntu runner proves repeatability. [VERIFIED: codebase grep `.planning/REQUIREMENTS.md`]  
**Warning signs:** `npm ci` logs optional dependency skips, or PNG hash differs across local macOS and CI Ubuntu. [ASSUMED]

### Pitfall 5: Required-Lane Contamination

**What goes wrong:** npm download failure blocks `mix ci`, `test`, signing proof, long-lived proof, or release proof. [VERIFIED: codebase grep `priv/guardrails/required_status_checks.json`]  
**Why it happens:** A `needs: test` edge, missing `continue-on-error`, or guardrail JSON promotion moves advisory tooling into the required graph. [VERIFIED: codebase grep `.github/workflows/ci.yml`]  
**How to avoid:** No `needs:`, `continue-on-error: true`, add to `advisory_contexts` only, and test absence from `required_contexts`. [VERIFIED: codebase grep `test/guardrails/required_checks_contract_test.exs`]  
**Warning signs:** `pdfjs-advisory` appears under `required_contexts` or required `test` job contains `npm`, `node`, or `pdfjs`. [VERIFIED: codebase grep `test/guardrails/required_checks_contract_test.exs`]
