    Apply exactly three mutations to the `test` job stanza in `.github/workflows/ci.yml`. No other job or line is touched.

    **Mutation 1 — Add `id: setup-beam` to the Setup Beam step (test job only).**
    The existing Setup Beam step has no `id:`. Add `id: setup-beam` as the second line of the step (after `- name: Setup Beam`). Do NOT change the `uses: erlef/setup-beam@v1` ref — SEC-01/Phase 112 is the SHA-pin phase. The `id:` exposes `steps.setup-beam.outputs.otp-version` and `steps.setup-beam.outputs.elixir-version` for the summary step.

    **Mutation 2 — Replace the bare `run: mix ci` step with a tee-capturing version.**
    The existing "Run CI" step is `run: mix ci`. Replace with:
    - Add `shell: bash` field.
    - Change `run:` to a block scalar with `set -o pipefail` on the first line.
    - Second line: `mix ci 2>&1 | tee /tmp/mix-ci-output.log`
    The `set -o pipefail` is mandatory — without it, `tee`'s always-zero exit code silently swallows a `mix ci` failure. The exit code of the pipeline must be the exit code of `mix ci`, not `tee`. This is a gate-neutral change: the job still exits non-zero if `mix ci` fails.

    **Mutation 3 — Append a CI Baseline Summary step after "Run CI" (still inside the `test` job).**
    The step MUST have:
    - `name: CI Baseline Summary`
    - `if: always()` — runs even when Run CI fails, so summary survives test failures
    - `continue-on-error: true` — a shell error in the summary cannot fail the job or change the gate outcome
    - `shell: bash`
    - `run:` block with a SINGLE brace-group redirect: `{ … } >> "$GITHUB_STEP_SUMMARY"`

    The brace-group body (in order):
    - `echo "## CI Baseline"` — the required H2 panel header (per D-02 specifics)
    - blank echo
    - `echo "| Property | Value |"` and `echo "|----------|-------|"` — Markdown table header
    - OTP row: `echo "| OTP | ${{ steps.setup-beam.outputs.otp-version }} |"`
    - Elixir row: `echo "| Elixir | ${{ steps.setup-beam.outputs.elixir-version }} |"`
    - Schedulers row: `echo "| Schedulers | $(elixir -e 'IO.puts(System.schedulers_online())' 2>/dev/null || echo 'n/a') |"`
    - Cache rows (placeholder for Phase 109 seam):
      ```

      echo "| Cache (deps) | cold / none |"
      echo "| Cache (_build) | cold / none |"
      ```
    - blank echo
    - `echo "### Slowest Tests"` and blank echo
    - `grep -A 25 'Top [0-9]* slowest' /tmp/mix-ci-output.log || echo "_(slowest data unavailable)_"`
    - All wrapped in single `} >> "$GITHUB_STEP_SUMMARY"` closing brace

    HARD constraints:
    - Do NOT emit multiple separate `>> "$GITHUB_STEP_SUMMARY"` writes — single brace-group ONLY (house style, avoids rendering inconsistency).
    - Do NOT add any step to any job other than `test`.
    - Do NOT change any `needs:`, `if:`, `continue-on-error:`, or other fields on any existing step.
    - Do NOT add cache keys, restore steps, or any other non-summary content.
