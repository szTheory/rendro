<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Default-branch control plane -> detached candidate | Trusted workflow/helper definitions interpret an exact untrusted candidate commit; candidate bytes never define their own authority. |
| Candidate outputs -> evidence bundle | Untrusted generated files cross a closed role/path/count/hash validator before upload. |
| Local deterministic proof -> remote renderer proof | ExUnit proves structure and rejection behavior; only paired Ubuntu/PDFium runs can prove raster payload identity. |
| Evidence transport -> durable authority | Expiring artifacts and archive digests are transport facts; Git controls, pinned definitions, committed normalized facts, and canonical repository content retain authority. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-135-01 | Spoofing | candidate identity | high | mitigate | Require `^[0-9a-f]{40}$`, detached checkout, and literal input-to-`git rev-parse HEAD` equality; comparator binds the same full SHA across all rows. |
| T-135-02 | Tampering | control plane vs candidate | high | mitigate | Keep control and candidate roots separate, mediate inputs through environment variables, disable persisted credentials, and validate candidate outputs with control-plane code. |
| T-135-03 | Tampering / Information disclosure | bundle filesystem | high | mitigate | Use literal role registries, `Path.safe_relative/1`, closed directories, uniqueness/count checks, and recomputed SHA-256 before accepting any payload. |
| T-135-04 | Information disclosure | runner token, secrets, caches | high | mitigate | Workflow contract requires `contents: read`, no secrets, no cache restore/save, no publication credentials, and `persist-credentials: false`. |
| T-135-05 | Elevation of privilege | workflow graph | high | mitigate | Forbid `workflow_run`, write/id-token/attestation permissions, repository mutation, and any edge to ordinary jobs or `ci-success`. |
| T-135-06 | Tampering | actions and PDFium supply chain | high | mitigate | Require full immutable action SHAs and existing PDFium version plus binary SHA-256 verification from `priv/pdfium_pin.json`. |
| T-135-07 | Repudiation / Tampering | artifact integrity | high | mitigate | Manifest binds control/candidate/run/attempt/renderer/commands and ordered payload hashes; sorted checksum index rejects missing, extra, duplicated, or changed files; archive digest remains transport-only. |
| T-135-08 | Elevation of authority | candidate/canonical/visual claims | high | mitigate | Candidate evidence excludes reviewer fields, canonical evidence never publishes, text states limits, remote parity does not claim visual quality, and existing `ci-success` topology stays unchanged. |
| T-135-09 | Denial of service | untrusted candidate execution / remote availability | medium | accept | Bound operations, payload counts, retention, and workflow timeout; remote unavailability is recorded and gates only Plan 03 cutover, never additive local completion. |
| T-135-SC | Tampering | package installs | low | accept | No npm/pip/cargo package install or dependency addition is introduced by this plan; existing lockfiles and pins remain unchanged. |

## Verification and Residual Risk

- Focused negative controls exercise candidate-SHA, path, role, digest, count, permission, pin, and authority failures locally.
- Residual candidate code can waste bounded runner time or emit malformed files, but it has no secrets/write credentials/cache and malformed output cannot cross bundle validation.
- Remote platform availability and human visual quality remain outside deterministic local authority; the former gates only final retirement and the latter stays with Phase 136.
</threat_model>
