<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| manifest -> filesystem | Record paths could traverse or substitute files. |
| historical source -> capsule | Facts/provenance could be rewritten or secrets imported. |
| record role -> returned fact | Stale roles or identities could gain authority. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-133-01 | Tampering / Information Disclosure | manifest path resolution | high | mitigate | Reject unsafe/absolute paths, symlinks/non-regular files, root escape, and digest mismatch before decode. |
| T-133-02 | Spoofing / Tampering | record roles and release bindings | high | mitigate | Strict schemas, uniqueness, role enum, and cross-record candidate/tag/version checks. |
| T-133-03 | Information Disclosure | imported records | high | mitigate | Preserve redaction assertions and reject secret names, home paths, process data, and binary proof bytes. |
| T-133-04 | Repudiation | digest authority claim | medium | mitigate | Store separate provenance and state Git/tag controls as authority per D-13. |

Every high-severity mitigation requires a passing negative-path test before summary creation.
</threat_model>
