# Phase 128 — UI Design Contract

> Visual and interaction contract for the static configurator. Generated by gsd-ui-researcher; verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — static HTML, CSS, and vanilla JavaScript only |
| Preset | not applicable |
| Component library | none; native semantic controls |
| Icon library | none; use text labels, not icon-only controls |
| Font | `var(--rendro-font-sans)` (Inter system stack); snippets use `var(--rendro-font-mono)` |
| Token source | `brand/tokens/tokens.css`; consume existing `--rendro-*` custom properties and do not duplicate token values |

The phase is not React, Next.js, or Vite; `components.json` and shadcn are not applicable. The configurator must inherit the existing explicit light/dark token behavior, including OS preference when no `data-theme` override is set.

---

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline label/status gaps |
| sm | 8px | Related controls and compact metadata |
| md | 16px | Default control, card, and panel spacing |
| lg | 24px | Panel padding and section-internal gaps |
| xl | 32px | Desktop column and primary section gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: all native picker controls and the copy button have a minimum 44px block size for pointer/touch use; no spacing-scale exceptions.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.625 |
| Label | 14px | 600 | 1.5 |
| Heading | 22px | 600 | 1.36 |
| Display | 28px | 600 | 1.29 |

Use the mono font at 14px/1.57 for generated Elixir snippets and compact catalog identifiers. Do not introduce a third weight; body uses 400 and all labels, headings, buttons, and selected control text use 600.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F7F3EA` light / `#1B1713` dark (`--rendro-bg-page`) | Page background and unraised layout areas |
| Secondary (30%) | `#FFFFFF` light / `#232019` dark (`--rendro-bg-surface`) | Configuration panel, preview frame, snippet card, and notices |
| Accent (10%) | `#2C6BED` light / `#7FA9FF` dark (`--rendro-accent`) | Primary copy action, selected picker indicator/border, focus ring |
| Destructive | `#C24132` light / `#E0715F` dark (`--rendro-feedback-error`) | Catalog-load and clipboard-error treatment only; there are no destructive actions |

Accent reserved for: the `Copy Elixir snippet` button, the selected state of each picker, and keyboard focus. The chosen document accent is represented only by its labeled swatch and the copied code; it must not recolor the configurator chrome or imply that a preview is generated live.

## Layout & Interaction Contract

- Render a single, centered page at `--rendro-grid-app-max` (1280px) with 24px horizontal gutters. Use a two-column grid at 900px and above: a 320px configuration panel beside the preview/output panel. Below 900px, stack configuration, preview, disclosure, then snippet in that order.
- Use native `<label>` + `<select>` controls for document family, preset, accent, and mode. Expose only values in the catalog manifest: six families, six presets, the seven curated hex accents, and light/dark. Do not supply arbitrary color entry or an open picker.
- Each selection change updates the query string with `family`, `preset`, `accent`, and `mode` using `history.replaceState`; reload restores the same valid selection. Validate every URL value against the manifest enum before applying it. Invalid, unknown, duplicate, or malformed values are ignored and the page falls back deterministically to the first catalog cell ordered by manifest position. Never insert URL values with `innerHTML`; use `textContent`, safe `setAttribute`, and constructed DOM nodes only.
- Resolve a preview by exact equality against the manifest's closed values, never by color-distance or other fuzzy matching. Show the selected preview image at its natural aspect ratio inside a bounded, scroll-free frame; `alt` and caption come from the manifest. Display the selected preview's family, preset, mode, and catalog accent in text.
- When the user's valid copied accent is represented by a different pre-rendered catalog row, place the information notice immediately above the preview: `Preview: nearest available catalog example. Copied code uses your exact accent.` State the represented catalog accent and the copied accent explicitly. This notice is factual, never a quality claim.
- For dark catalog cells, render the manifest's `boundary_disclosure` verbatim directly below the preview, in the warning treatment. Do not make print, accessibility, PDF/UA, WCAG, or design-quality claims.
- Put the canonical generated Elixir snippet in a visible, selectable `<pre><code>` block below the preview. The `Copy Elixir snippet` button copies precisely that text through the Clipboard API; on success, change its visible label to `Snippet copied` for 2 seconds, then restore the original label without moving focus. On failure, retain the snippet and show the documented error state with a retry action.
- Keep the static page honest: it selects shipped raster artifacts; it does not render a PDF, submit a form, persist data, or contact a server. The Livebook adds code cells only and has no browser UI contract beyond using the same canonical snippet text.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Copy Elixir snippet |
| Copy success feedback | Snippet copied |
| Nearest-preview disclosure | Preview: nearest available catalog example. Copied code uses your exact accent. |
| Empty state heading | No catalog preview matches this selection |
| Empty state body | Choose a preset, accent, mode, and document family from the available catalog options. |
| Loading state | Loading catalog previews… |
| Error state | Couldn’t load the catalog or copy the snippet. Reload this documentation page and try again. |
| Dark-preview disclosure | Use the catalog cell’s exact `boundary_disclosure`: `Screen-oriented; not a print, accessibility, PDF/UA, or WCAG claim.` |
| Destructive confirmation | None — this phase has no destructive action or persisted user data. |

## UI Considerations

Applicable state considerations resolved: 8 covered, 0 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Preview result | ✅ covered | No exact catalog match renders the documented empty-state heading/body; the existing snippet remains unavailable until a valid match resolves. |
| loading | Catalog manifest and preview image | ✅ covered | The page shows `Loading catalog previews…` while its local manifest and selected image are pending. |
| error | Catalog manifest, preview image, clipboard action | ✅ covered | A load or copy failure renders the documented error message, preserves valid picker values and snippet text where available, and provides retry through reload/copy again. |
| partial | Four picker controls | ✅ covered | Before a complete valid four-part selection, controls use the deterministic manifest-first fallback; no partial URL value is rendered as trusted display text. |
| overflow | Snippet, preview caption, catalog metadata | ✅ covered | Snippets scroll horizontally in their code container; captions and metadata wrap at word boundaries; preview images scale down to their panel width without cropping. |
| long-text | Labels, generated snippet, manifest-provided caption/disclosure | ✅ covered | Picker labels and notices wrap; the code block scrolls; manifest text is inserted only with safe DOM APIs. |
| populated | Preview result | ✅ covered | A resolved result displays one manifest-backed raster, its exact caption/alt metadata, factual preview relationship notice when needed, and a canonical copyable snippet. |
| zero-one-many | Manifest result candidates | ✅ covered | The UI presents exactly one resolved preview. Zero candidates show the empty state; one candidate is shown directly; multiple exact candidates resolve by manifest order and are not presented as an unbounded gallery. |
