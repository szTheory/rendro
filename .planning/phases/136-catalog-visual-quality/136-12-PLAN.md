## Machine-readable receipt contract

`136-12-RECEIPT.json` has `schema_version: 1`, a unique `receipt_id`, and exactly one variant:

- Complete: `status: complete`; full `candidate.sha`; `control.ref` and full `control.sha`; `run.id` and positive `run.attempt`; `renderer.version`, full `renderer.binary_sha256`, and positive `renderer.dpi`; distinct `artifacts.evidence` and `artifacts.reviewer_packet` objects each with unique numeric/string `id`, exact `name`, API `url`, provider `digest`, and computed lowercase 64-character `archive_sha256`; exact unique authoritative `roles` with role/path/hash/count; exactly eight `review_images` with ordinal 1..8, unique fixed `review_role`, unique safe relative `path`, catalog ID, control/target kind, PNG/source-PDF SHA-256, and authoritative bundle role/path; and `validation` containing detached `control_checkout_sha`, closed-bundle result, packet-binding result, fresh download nonce/paths, and validation timestamp.
- Unavailable: `status: unavailable`; unique `receipt_id`; candidate/control identities; `failure.stage`, stable `failure.code`, exact message, expected facts, observed facts, and next action; exact six `targets_unpromoted`; empty `review_images`; and `revision_gate` with positive `iteration`, `cap: 3`, `status: retry_required|escalated`, and prior receipt IDs. Run/artifact/renderer observations are recorded when they exist and explicitly null otherwise—never omitted or guessed.

Both variants reject duplicate role/path/artifact IDs, unknown fields that could carry reviewer authority, non-full hashes, nonpositive run attempts, and inconsistent candidate/control/run/renderer facts. The general validator accepts either truthful shape; the task completion gate additionally requires `status: complete`.

## Bounded Revision Gate

Negative receipts never close a task, plan, requirement, or phase truth. The receipt chain starts at iteration 1 and caps at 3:

1. Record the exact failed stage, candidate/control/run/attempt/artifact facts, affected target IDs if deterministically known, all unpromoted targets, and prior receipt IDs. A provider/authorization failure has no invented visual miss and therefore no visual-source edit.
2. For a deterministic target defect, change only the implicated D-01 target profile and its directly owned tests; preserve all unaffected target/control hashes. For an evidence-path defect, change only the failing dev/workflow/runbook contract. Do not create visual churn to manufacture a new SHA.
3. Commit the scoped correction as a new immutable candidate, rerun Plans 09-11 and 14 deterministic validation, then rerun this plan with a fresh run and two fresh downloads. Review resumes only from Plan 13's fresh intake.
4. Increment `revision_gate.iteration`. After iteration 3 fails, set `status: escalated`, preserve all receipts, return `CHECKPOINT REACHED` with the exact blocker and next required authority, leave canonical bytes unchanged, and keep CATALOG-11/CATALOG-13 plus the phase goal open.
