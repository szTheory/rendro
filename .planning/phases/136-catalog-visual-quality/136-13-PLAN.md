## Bounded Revision Gate

The gate applies to unavailable, incomplete, threshold-miss, provenance-mismatch, and packet-mismatch outcomes. It is not a successful branch.

1. Start at iteration 1 and cap at 3. Each attempt preserves its Plan 12/13 receipt IDs, exact candidate/control/run/attempt/artifacts, intake nonce, review truth, failed stage, target set, and canonical before/after hashes.
2. For each threshold-miss attempt, set `failed_target_ids` to the exact canonical-order set of every target whose complete review record misses D-23. That set is the complete modification allowlist for the attempt: only those private presentation profiles and directly owned tests are eligible to change. Relative to the prior immutable candidate, require all `6 - count(failed_target_ids)` complementary target IDs and all 26 controls to remain byte-stable; require any actual changed target ID to be a member of `failed_target_ids`. An empty set permits no visual-source edit and routes only to fresh evidence/review over the same immutable content. An all-six set permits all six target profiles to change and therefore requires zero unaffected target hashes plus all 26 control hashes to remain stable. A `missed` variant cannot have an empty set; incomplete/unavailable variants do not infer misses from absent feedback.
3. For deterministic/provenance defects, change only the implicated dev/workflow/runbook contract. For unavailable or incomplete human feedback, do not invent a visual defect or edit visual bytes; retain the phase truth as open and request a fresh review intake.
4. Every scoped correction becomes a new immutable candidate SHA, runs the complete deterministic Plans 09-11/14 validation, then creates a fresh Plan 12 run with two fresh artifacts and a fresh Plan 13 intake/review. A transient provider/reviewer retry uses a new exact run/attempt and remains tied to the same immutable content until an actual scoped correction justifies a new SHA.
5. Increment the iteration only after a complete attempt outcome is recorded. The three-attempt cap bounds retries and does not guarantee visual closure. After iteration 3 remains nonqualified, set `revision_gate.status: escalated`, preserve all receipts and reviewer records, return `CHECKPOINT REACHED` with the exact unresolved targets/stage and required next authority, leave canonical output unchanged, and keep CATALOG-11/CATALOG-13 plus the phase goal open.

Optional human comments can enrich a receipt but never alter deterministic pass/fail. Conversely, missing optional feedback does not erase deterministic completion, yet the objective six-review requirement remains truthfully unachieved and the gap chain remains incomplete.
